# Conversation Lab (voice-lab)

Текстовый полигон для Веры: только «текст → LLM → текст», без аудио,
телефонии и баз данных. Здесь оттачивается РАЗГОВОР, пока не пройдён
Gate 1 — никакой работы над голосом.

## Запуск

Интерпретатор — рантайм-venv (в нём есть numpy/mlx/transformers):

```bash
PY="/Users/earflow/Library/Application Support/MossVoice/runtime/qwen-venv/bin/python"

# REPL (обычный разговор; Вера не задаёт вопросов приветствия)
$PY voice-lab/lab.py

# REPL со служебным звонком (Вера открывает разговор вопросом о самочувствии)
$PY voice-lab/lab.py --check-in

# Gate 1: 100 сценариев -> отчёт в voice-lab/reports/
$PY voice-lab/run_gate1.py
$PY voice-lab/run_gate1.py --fallback   # без LLM, только безопасные фразы
```

`--url http://host:port` переключает на другой LLM-демон (для бенчмарка
сильной модели запустите второй `llm_server.py` с моделью крупнее и
укажите его адрес).

## Сильная модель (бенчмарк 2026-08-20)

- **1.7B → 4B:** `Qwen3-1.7B-8bit` давал мутантов («Дождь — это нечто
  несчастное», «Позвоните в близких»). Сравнение корпуса: отчёт 1.7B —
  `reports/gate1_20260820_050044.md`, 4B — `reports/gate1_20260820_050414.md`.
  Прод-демон 9500 переведён на `mlx-community/Qwen3-4B-8bit`.
- **Скриптовый safety:** в `safety_confirm`/`safety_active` LLM-фразы
  отключены — контрольный вопрос и реплики при опасности всегда точные
  скриптовые (модель больше не ломает петлю подтверждения, гейт #62).
- Вердикты детерминированы SafetyEngine'ом и не зависят от модели: корпус
  даёт одинаковое распределение (done=8 · ok=29 · attention=6 · alert=8)
  на 1.7B и 4B — меняется только текст реплик.

## Что именно исправлено в движке (Этап A)

Режимы вместо шагов: `companion` (по умолчанию), `check_in`, `clarify`,
`safety_confirm`, `safety_active`, `closing`.

1. **Убрана анкета.** Двухшаговый опрос (самочувствие → помощь → до свидания)
   вырезан из основного пути. Разговор заканчивается только при явном
   прощании, подтверждённой опасности или внешнем завершении звонка.
2. **Повтор реплики исправлен.** Текущая реплика добавляется в историю LLM
   один раз (было дважды).
3. **Инструкция — в system-контекст.** Цель ответа больше не подсовывается
   моделью как сообщение пользователя.
4. **Без вопроса после каждой реплики.** Промпт прямо запрещает анкетность;
   в режиме `ok`/`unknown` Вера просто откликается.
5. **Голое «да» не просьба о помощи.** `help_request` от движка принимается
   только при явной просьбе («нужна помощь», «помогите») или когда Вера сама
   только что задала вопрос о помощи.
6. **Безопасность усилена, а не ослаблена.** Gate 1 (первый прогон) нашёл
   ложные срабатывания движка — исправлены и закрыты инвариантами I13–I17:
   «встала/поднялась» ≠ RED (RED = «не встаю», «не могу встать»);
   «кровать» ≠ «кровь» (кровотечение — только точные формы);
   прошедшее время «купила хлеб/позвонила дочери» ≠ запрос помощи
   (императив «купите/позвоните» и «нужно/надо» — запрос);
   «листья/снег/дождь падают» ≠ падение человека;
   добавлены травмы «обварилась/обожглась/ожог» → RED.

## Gate 1 — критерий перехода к Этапу B (latency)

90 из 100 сценариев выглядят нормально для человека. Чек-лист на каждый
сценарий (в отчёте): не повторяется, не анкета, помнит контекст, не хамит,
на «вы», без «круто», не сюсюкает, без странных советов, меняет тему, умеет
слушать.

Пока Gate 1 не пройден — TTS/телефония/задержки не трогаем.
