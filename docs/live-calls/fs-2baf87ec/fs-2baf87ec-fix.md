# fs-2baf87ec: исправление semantic binding и повторного concern probe

Дата: 2026-10-01. База: `919dfba` / runtime-код `04cf7ba`.
Ветка публикации: `feature/voice-zoiper-m5`, main не меняется.
Источник: [расшифровка и гипотезы агента](fs-2baf87ec-clarification-loop.md).
Это текстовый повтор; исходное аудио/JSONL с Mac здесь не доступны.

## Уточнённая причина

Первый неверный переход — «нормально» из вопроса про еду связывалось с
головной болью в другом предложении. Общий kernel clause splitter не
разделял `.?!`; nearest-issue binding создавал current=False, а проекция
проверяла слова о разрешении симптома во всей реплике.

После «две недели» episode consumer действительно сохранял полный ответ
в onset. Пустые mentions/facts из отчёта не доказывают потерю ответа.
Ошибки ниже по цепи: словесное количество не выделялось как DURATION,
reference TIME «Это» попадал в onset observation; старый coverage filler
сохранялся при раннем возврате к episode plan; после завершения вопросов
отрицательный wellness и пустой wellness_concern снова запускали общий
concern probe без учёта записанных эпизодов.

В расширенном replay обнаружены ещё два обхода grounding: reference fallback
записывал всю фразу как duration по одному наличию «недел/утр»; slot classifier
и personal phrase memory записывали raw_text в clinical attribute по общему
вердикту answer. Поэтому новая дрожь и мета-просьба становились severity
головной боли. Буквальная цитата не доказывает клинический смысл значения.

Отдельно: kernel строил spoken label из леммы `рука` + `ноют`; kernel и
legacy labels добавлялись как два mentions одной боли. Site-only dedup в
episode ingest выбрасывал разные симптомы одной локализации. «Трястись»
не было в словаре, а итоговый recap не показывал дополнительную дрожь.

## Замена у существующих владельцев

- Clause splitter учитывает предложения и контраст. STATUS не связывается
  с более поздним анатомическим подлежащим после независимой оценки.
- Spoken noun сохраняет форму из речи; лемма остаётся ключом. Existing
  canonical «головная боль» сохранено без второго mention той же боли.
- DURATION поддерживает цифровое/словесное количество. REFERS_TO span
  исключён из временных фактов; onset observation получает настоящую
  временную цитату. Out-of-order duration не заполняет severity/current;
  неизвестный ответ и уже записанное значение защищены.
- Количество от другого predicate owner (лекарства, планы, другой человек)
  не переносится в боль. Reference fallback удалён; REFERS_TO не обходит
  проверку ownership. Coarse classifier/memory answer требует grounded
  temporal/severity value и не обучает память на отвергнутом значении.
- Просьба уточнить/конкретизировать вопрос идёт по existing repair path.
  Запрос с настоящим симптомом проходит через kernel, не исчезает в LEVEL0.
- Acute episode branch снимает pending coverage до return. История
  заземлённых speaker episodes выключает повтор общего concern probe,
  кроме нового неопределённого ухудшения; safety/RED приоритет сохранён.
- Reflexive tremor распознаётся, «трясу коврик» не считается жалобой.
  Общая anatomical subject может принадлежать боли и дрожи одновременно.
  Ingest сохраняет разные симптомы одной локализации; recap отражает дрожь.
- Прошлая боль с неизвестным нынешним состоянием не получает выдуманное
  «полегчало, рада»; такое acknowledgment требует настоящего улучшения.
- Полная tremor clause сохраняет исходное «кровят» как evidence. Оно не
  подменяется кровотечением, «крутят» или другим выдуманным значением.

Новых моделей, флагов, planner, сервисов и TTS-переписывания нет.
Замороженный action-policy manifest и исходные тестовые ожидания не менялись.

Точные реплики исходного звонка не содержат ответа о тяжести головной боли.
После исправления эту тяжесть нельзя выдумывать ради completed-call. Если
неясные ответы исчерпывают попытки, сохраняется существующий честный
partial close с одним прощанием; варианты с «Терпимая / Не помню» должны
пройти обычное продолжение/снятие неизвестного вопроса.
