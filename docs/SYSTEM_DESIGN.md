## 0. Одна фраза, из которой выводится всё остальное

**Вера — это заботливая собеседница с детерминированными гарантиями безопасности,
а не автоответчик и не свободный чат-бот.**

Из неё следует каждое решение ниже. Где фраза конфликтует с реальностью
(латентность, железо, данные) — побеждает реальность, и это записано явно.

## 1. Что система обязана делать (и чего обязана НЕ делать)

Обязана:
1. Дозвониться обычному человеку на обычный телефон и провести тёплый связный
   разговор 3–7 минут, без приложений с его стороны.
2. Понять, что с человеком: жалобы (что/где/как сильно/с каких пор/лучше-хуже),
   настроение, сон, планы, лекарства, еда — и что его волнует прямо сейчас.
3. Помочь в разговоре: посочувствовать, спросить «чем помочь», предложить передать
   родным, при красных флагах — действовать по safety-протоколу, никогда не бросать
   страдающего фразой «не получилось узнать».
4. Собрать информацию так, чтобы семья получила честный статус
   GREEN / YELLOW / RED / NO_CONTACT / TECHNICAL / DECLINED и понятную сводку
   («беспокоили головная боль и боль в животе»), а не blob текста.
5. Отвечать быстро: пауза «человек замолчал → Вера говорит» ~1.2–1.5 с номинально,
   никогда тишина >3 с без звукового маркера («минутку, записываю»).
6. Не врать: ни одного факта семье, которого нет в grounded evidence; ни одного
   обещания действий («вызову скорую»), которых система не выполняет.

Не обязана (non-goals, сознательно):
- Быть психотерапевтом, врачом, юристом — только внимательный сбор + эскалация.
- Развлекать, болтать бесконечно — звонок конечен, 3–7 минут, cap на ходы.
- Знать всё о человеке заранее — только профиль миссии и память прошлых звонков.
- Работать без света/интернета у оператора — деградация честная (TECHNICAL), не тишина.

## 2. Архитектура: один владелец на слой

```text
                         ┌────────────── IMVERA Core ──────────────┐
                         │ вердикты, эскалация, семья, расписание  │
                         │ (прод: внешний; сейчас: services/core)  │
                         └──────────────▲─────────────▲────────────┘
                                        │ события     │ статусы на чтение
                                        │ (spool)     │ (read-only mirror)
┌──────┐  ┌───────────┐  ┌───────────────┴─────────────▼────────────┐
│ SIP  │  │ FreeSWITCH│  │                 VOISEUP                  │
│опера-│─▶│mod_imvera │─▶│ CallActor (realtime: кадры, отмена,      │
│ тор  │  │_audio     │  │ generation_id, barge-in, дедлайны)       │
└──────┘  └───────────┘  │   ↓ VAD → GigaAM (STT, 0.5с)             │
                         │   ↓ TurnUnderstanding (модель+ruli,      │
                         │     model-first, валидатор верховный)    │
                         │   ↓ Reducer → EngineState (ЕДИНСТВЕННЫЙ  │
                         │     авторитет правды; только код пишет)  │
                         │   ↓ HardConstraints (safety/stop/consent │
                         │     /asked-set/mission — код, без LLM)   │
                         │   ↓ CandidateMoves (код, 2–5 вариантов)  │
                         │   ↓ ConversationComposer (Qwen: выбрать  │
                         │     ОДНО + озвучить bridge; Cut 1+)      │
                         │   ↓ HardValidator (код, верховный; fail  │
                         │     → детерминированный fallback)        │
                         │   ↓ Silero/MLX TTS → FreeSWITCH → ухо    │
                         │                                          │
                         │ Рядом (не в горячем пути): persistence   │
                         │ (переходы/факты/аутбокс — engine-native, │
                         │ ADR-019), StatusEngine (статус из жалоб, │
                         │ НЕ из галочки миссии), traces/outbox в   │
                         │ Core, метрики/майнинг провалов.          │
                         └──────────────────────────────────────────┘
```

Таблица владения (нарушение любого пункта = баг архитектуры, не фича):

| Слой | Владелец | Ему можно | Ему нельзя |
|---|---|---|---|
| Transport (SIP/RTP/bridge) | `telephony/` | кадры, отмена генерации, break | говорить как Вера, переписывать текст |
| Realtime (CallActor) | `voice_runtime/` | дедлайны, очередь, barge-in, `generation_id` | решать, ЧТО сказать |
| Understanding | kernel + act-модель + XEnc | кандидаты актов/связей/сущностей | закрывать слоты, менять state |
| Validator (семантика) | детерминированный код | отклонить кандидата → fallback | гадать |
| State | Reducer + EngineState | единолично менять правду | два мозга, две FSM в проде |
| Safety | код (stop/consent/RED/wrong-person) | exact-фразы, обход всего | через LLM |
| Strategist (ADR-020) | CandidateMoves (код) + Composer (Qwen) | выбрать 1 ход из разрешённых + bridge | мутировать state, ставить вердикты |
| SpeechValidator | код | отклонить bridge → fallback | пропускать «почти норм» |
| Renderer/TTS | шаблоны + TTS | `canonical == spoken`, побайтово в трейс | импровизация |
| Verdicts | Core (SafetyEngine/StatusEngine-проекция) | RED/YELLOW/GREEN семье | voiseup ставит RED сам |
| Persistence | engine-native store | переходы, факты, аутбокс | синхронный DB/S3 в горячем пути |

Запреты (из AGENTS.md, действуют): две FSM/два мозга в проде; транспорт говорит как Вера;
скрытые фолбэки; «тесты зелёные = прод готов»; TECHNICAL/NO_CONTACT как GREEN;
молчание = согласие; стабы `return ok` в прод-путях; новая архитектура при открытых
гейтах ADR-014 (поэтому всё новое — нарезкой Cut 0–4, каждая шипабельна).

## 3. Разговор: как Вера должна думать (ADR-020, кратко здесь)

Ход живого звонка:

1. **Слушать.** VAD + partial STT; barge-in человека останавливает генерацию
   (транспорт уже умеет: cancel + LOCAL_PURGE_ACK + downstream break; живой пруф —
   гейт, не галочка).
2. **Понять.** Model-first act → rules/kernel → spans/issues → relation (shadow
   сейчас, narrow authority в Cut 3) → RichUserTurn. Ошибка/таймаут → rules, звонок
   не ждёт, в трейс `fallback`.
3. **Проверить.** Safety/стоп/согласие/не-тот-человек — детерминированно, мимо модели.
4. **Выбрать ход.** Код строит 2–5 кандидатов (`FOLLOW_USER_THREAD`, `REFLECT`,
   `ACK_ONLY`, `ASK_GOAL`, `CLARIFY`, `TRANSITION`, `RESUME_MISSION`, `CLOSE`);
   coverage — мягкая цель (utility), не владелец (Cut 4; до него FILLER_ORDER как
   tiebreak). Composer выбирает один + пишет bridge. Вопрос — детерминированный
   до Cut 2, из allowed-списка после.
5. **Проверить речь.** Bridge: без `?`, ≤25 слов, без обещаний/вердиктов/новых фактов,
   не попугай. Fail → python-фраза. Safety/terminal/summary — exact всегда.
6. **Сказать и доказать.** TTS получает байт-в-байт canonical; в трейс: текст, хеш,
   generation_id, задержки стадий. `canonical_assistant_text == phone_spoken_text`.

Дискурс (поля EngineState, пишет только код): `current_thread`, `open_hook`,
`asked_signatures` (8), `last_ack_signature`, `user_burden`. Без них «она слушает»
невозможно технически — это не косметика.

Характер (выбран владельцем: заботливая собеседница): реагировать на сказанное,
а не читать чек-лист; отказ датировать («не помню когда») принимается один раз и
больше не спрашивается; свежая сильная боль называется вслух; при открытых жалобах
в финале — предложение помощи, никогда give-up «до свидания».

## 4. Данные: что хранится и зачем

- **EngineState** — правда звонка: слоты, цели, эпизоды жалоб (site/subject/attrs),
  asked/доставленные вопросы, consent, safety. Единственный источник для речи.
- **Evidence** — каждая цитата привязана к utterance_id + pcm_sha256. Факт без
  evidence семье не уходит. Правило Q0.1: persist только при изменении (value, source).
- **Traces** (`.run/traces/*.jsonl`) — посекундная правда: стадии с ms, тексты, хеши.
  Это и отладка, и сырьё маховика качества, и доказательство в споре.
- **Outbox → Core** — события и снапшоты со статусом; spool с ретраями, не «fire-and-forget».
- **Память звонков** — что сработало/нет (personal hypotheses после 3 хитов), дискурс
  прошлого звонка («в прошлый раз болела голова» — только с evidence).
- **Датасеты/артефакты** (`datasets/`, `models/`, gitignored) — сиды, eval-пары,
  калибровка; в git только скрипты + MANIFEST + sha. Модель без MANIFEST в прод не едет.

## 5. Безопасность и честность (не делегируются)

- Safety-сигналы (падение/боль в груди/«умираю»/суицид — по спецификации),
  stop, отзыв согласия, не-тот-человек, RED — детерминированный код, exact-фразы,
  мимо LLM и мимо Strategist. Тесты — красные команды, не только happy path.
- Voiseup ставит максимум YELLOW-пол по grounded-жалобам (уже сделано); RED —
  только Core ack. Семье никогда: TECHNICAL как GREEN, тишина как ответ, факт без цитаты.
- Секреты/PII: трейсы с голосом — локально, ретеншн зафиксирован; в git ни wav, ни ключей.
- Каждый claim о проде — командой с выводом или NOT VERIFIED. «Готово» без VERIFIED запрещено.

## 6. Скорость: бюджет, а не надежда

Бюджет хода: STT 0.6 + interpret 0.25 + policy 0.1 + composer (deadline 0.8, fallback
мгновенный) + TTS 0.3 ≈ **1.25 номинал / ~2.0 худший**. Всё сверху — именованный баг.
Правила: модели греются на старте (никогда лениво в звонке — измеренные 6.2 с);
MPS только main-thread; partial STT не-заглушка; тишина >3 с запрещена (маркер
«записываю»); barge-in доказывается ухом, не ACK.

## 7. Наблюдаемость и маховик (единственное, что compounding)

Каждый живой звонок автоматически: трейс → майнер провалов (re-ask, give-up, неверный
fill, тишина >3 с, topic-jump) → тест-кейсы + очередь разметки → фикс/дообучение →
замер на следующем звонке. Метрики рядом со старыми гейтами: topic-ignored rate,
unnatural-jump rate, repeat rate, already-known rate, ack-relevance, thread continuity,
groundedness, mission completion, safety violations (=0), p50/p95, composer fallback
rate. База — в Cut 0, иначе «стало лучше» нечем доказать.

## 8. Порядок строительства (что за чем, с гейтами)

1. **Операционка** (вне кода): GitHub billing → CI зелёный; `main`↔`feature` свести;
   `:9103` поднять. Без этого всё остальное — слова.
2. **Cut 0** (ADR-020): бенчмарк Qwen p50/p95, базовые метрики, поля дискурса +
   ContextPack + каталог (мёртвый код, тесты), ноль изменений поведения.
3. **Живой пруф скорости**: barge-in ухом + turn-budget на 7000; прогрев моделей
   (вечно горячие) как часть готовности.
4. **Cut 1**: LLM bridge с валидатором; differential-дельты как blessed-expected.
5. **No-abandonment**: offer помощи вместо give-up (фразы → differential-контроль).
6. **Cut 2–4**: выбор ходов → relation полномочия → coverage-как-utility.
7. **100 звонков** (ADR-014) → приёмка → только потом новые фичи/железо/прод.

## 9. Открытые вопросы (честно, с владельцами)

- Qwen p95 на lab Mac — НЕ ИЗМЕРЕН (Cut 0). Владелец решения при превышении: кэш
  bridges / меньшая модель / только Cut-1-объём.
- PSTN-транки мертвы (Novofon дроп, VoxImplant 403) — пилот только lab/Zoiper, пока
  владелец не решит телефонию.
- Прода нет физически (сервер/GPU/мониторинг) — lab only до решения владельца.
- Ретеншн голоса и согласия пожилых в проде — нужно решение + security-privacy проход.

## 10. Критерий «спроектировано правильно»

Система спроектирована правильно, если новичок по этому файлу может ответить без
гадания: кто владеет каждым решением; где проходит граница модель/код; что
происходит при отказе каждого компонента; какой следующий гейт и чем он меряется.
Всё остальное — детали, которые меняются. Этот файл — нет, только через ADR.
