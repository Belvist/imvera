Ближе всего к **формату короткого звонка заботы** — inTouch Morning Check-ins
и CLOVA CareCall. Для **манеры общения и companionship** полезны также QuikTok
и ElliQ. Fish/Newo относятся к платформам, на которых можно построить такой
сервис. Эта классификация не является рейтингом качества.

Название EverFriends найдено; публичная страница отдаёт в основном JS-shell
и title «Video AI Companions for Seniors & Caregivers». Детали не подтверждены,
поэтому продукт не включён в сравнительную таблицу. Sensi.ai здесь вернул 403;
его свойства и качество не оценивались.

## Что перенести в инженерные критерии

CLOVA публикует исследование памяти: анализ логов и интервью с **девятью**
пользователями; это не независимое сравнение с IMVERA и не клиническая гарантия.
Память касается здоровья, еды, сна, посещённых мест и домашних животных.
Пользователи описывали более личное общение при уместном воспоминании.
Исследователи отдельно отмечают раздражение, когда система снова спрашивает
о хроническом заболевании. Практический критерий для нас: вспоминать только
подтверждённые сведения, обозначать их время, давать возможность исправить
и не возвращать уже закрытый/нежелательный вопрос ради демонстрации памяти.

inTouch описывает Morning Check-in как короткий, структурированный, мягкий
разговор без давления, с итогом для care staff. Для IMVERA это означает:
один понятный вопрос, уважение отказа/незнания и объяснение переходов.
Проценты эффективности, claims о dementia risk и «world's first» на сайтах
не считаются нашими проверенными метриками.

## Проведённое сравнение

Заморожен набор из **16 русскоязычных текстовых сценариев**:
[`dialogue_comparison_v1.json`](../../tools/voice_lab/fixtures/dialogue_comparison_v1.json).
Входы синтетические; обобщение на независимой реальной речи здесь не измеряется.
Одинаковый набор прогнан на IMVERA до изменения (`b5adf12`) и на новом дереве.
Сравниваются реальные канонические ответы движка, исходные реплики и итоговые
SDK-наблюдения. Открытые кейсы не объявляются успешными: их текущий outcome
может оставаться TECHNICAL/PARTIAL. Это незавершённая текстовая симуляция,
а не автоматически проваленный телефонный звонок.

Результат этого сравнения и полных проверок — в [current-task](../current-task.md).
Там же отмечено, что изменения в Renderer проверяются отдельно: часть
сценариев движка идёт по более ранним существующим веткам, а не через новый ack.

**Прямой тест ответов конкурентов: NOT_RUN.** Ни одной их реплики на этом
наборе не получено. Сайты/документация не заменяют разговор, чужие проморолики
не выдают результат на наших входах. Нельзя ставить им ноль, выдумывать ответы
или объявлять IMVERA победителем. Owner запрошен о тестовом доступе.

## Воспроизводимый протокол

1. Зафиксировать provider, agent/model/config version, язык, канал и время.
   На Fish/Newo настроить одинаковые цели, личность AI-помощника и ограничения
   действий. Неподдерживаемые задачи отмечать UNSUPPORTED, без оценки качества.
2. Для первичного сравнения использовать один русский набор и одинаковую
   информацию о человеке. Перевод на английский/корейский — отдельный набор;
   результат не смешивать с русским рейтингом.
3. В каждом сценарии начать новую сессию и записать реальный opening и каждый
   ответ. Сохранить оригинал транскрипта/записи и источник; не редактировать
   ответы под ожидаемую формулировку. Пустой ответ записывать как `[]`.
4. Текст сопоставлять с текстом, телефон с телефоном. Для телефонного прогона
   записать STT, codec/8 kHz, шум, доступные provider versions, задержки и barge-in.
   У нас этот слой ещё не пройден. Оплаченные API и реальные люди не вызывались.
5. Минимум три русскоязычных оценщика отдельно оценивают 1–5: теплоту без
   чрезмерности, уважение, уместность реакции, понятность переходов, нагрузку
   вопросами. Дать случайные метки A/B; оригиналы и сведения о бренде хранить
   отдельно. Любая редакция для ослепления фиксируется, оригинал сохраняется.
6. Отдельно считать фактические ошибки, ложные обещания/диагнозы, потерю жалобы,
   повтор уже закрытого вопроса, соблюдение отказа, completion, p50/p95 и
   остановку речи при перебивании. Наличие слова «понимаю» не является оценкой
   эмпатии. Автоматический warmth/MOS score здесь не реализован.

Инструмент: [`dialogue_comparison.py`](../../tools/voice_lab/dialogue_comparison.py).

```bash
python tools/voice_lab/dialogue_comparison.py run \
  --label IMVERA --output /tmp/imvera-capture.json
python tools/voice_lab/dialogue_comparison.py import \
  --capture /tmp/real-competitor-capture.json --output /tmp/validated-capture.json
python tools/voice_lab/dialogue_comparison.py compare \
  --left /tmp/imvera-capture.json --right /tmp/validated-capture.json \
  --output /tmp/comparison.md
```

Для before/after использовать один и тот же инструмент и fixture с разными
`PYTHONPATH`/cwd, указывающими на рабочее дерево соответствующей версии продукта.
Baseline JSON и отчёт comparison лежат вне репозитория и не участвуют в
статусе dirty проверяемой версии. Программа проверяет schema, suite SHA,
атрибуцию, порядок/точность входов, язык и канал. Она не устанавливает
подлинность чужой записи: `evidence_ref` требует ручной проверки.

Формат capture:

```json
{
  "format": "imvera.dialogue-comparison.v1",
  "suite_sha256": "SHA256 фактических байтов fixture",
  "provider": {
    "name": "реальный провайдер", "version": "версия агента/конфигурации",
    "channel": "text", "language": "ru", "captured_at": "ISO timestamp",
    "evidence_ref": "путь к оригиналу либо URL тестовой сессии"
  },
  "cases": [{
    "id": "unknown_onset",
    "turns": [
      {"user": null, "assistant": ["реальный opening"]},
      {"user": "Голова болит.", "assistant": ["реальный ответ"]},
      {"user": "Не помню.", "assistant": ["реальный ответ"]},
      {"user": "Терпимая.", "assistant": ["реальный ответ"]}
    ]
  }]
}
```

Это описание формата, а не измеренная реплика конкурента. Можно импортировать
часть кейсов; отчёт показывает реальный знаменатель и NOT_RUN для остальных.
Ключи/пароли получать через подключённое окружение, не сохранять в fixture,
capture, логах или Git. Публичные ссылки sign-in не являются авторизацией.
