## Что это за проект

Голосовой агент заботы о пожилых: телефонный звонок → распознавание речи →
диалог с Веры (тёплый, с памятью контекста) → вердикт безопасности →
уведомление семьи. Полностью офлайн на CPU, в Docker-микросервисах.

## ЕДИНЫЙ МАРШРУТ (директива владельца 2026-08-21 — действует, остальные планы заморожены)

```text
1. ВЫБРАТЬ ГОЛОС            ← МЫ ЗДЕСЬ (базовая линия снята)
2. ПРОИЗНОШЕНИЕ             (VeraSpeechFrontend — сделан: SSML-паузы,
                             числа/даты, ударения, мастеринг)
3. CONTINUOUS AUDIO         (убить record→WAV→HTTP→playback)
4. STREAMING STT            (распознавание во время речи)
5. STREAMING TTS + BARGE-IN (100–250 мс до тишины)
6. <1–1.5 с до первого звука (latency trace на каждую реплику)
7. 20 × 5-мин звонков без сбоев
8. РАЗМОРОЗКА PRODUCT CORE  (consent/schedule/UI/billing)
9. SCALE/CELLS              (по §16 плана)
```

**Заморожено до конца маршрута:** новые таблицы, billing, UI, Kubernetes,
Temporal, cell router, новые safety-правила, новые арх-документы, обучение
VeraVoice. Не трогать без прямого указания владельца.

## Текущее состояние (обновлено 2026-08-23)

- **Стек (прод, Docker):** Silero TTS ru v5 (голос kseniya, SSML-фронтенд,
  мастеринг) · faster-whisper **tiny** fp32 (STT, Silero-VAD шумогейт) ·
  llama.cpp + Qwen3-4B Q4_K_M (LLM, OpenAI-протокол, thinking off,
  keep-alive) · Postgres/Redis/MinIO · workflow-worker (outbox/incidents
  отдельно от realtime) · FreeSWITCH на хосте (ext 4400, кусочная запись).

## ПРАВИЛА: как правильно строить логику диалога (state machine) — ОБЯЗАТЕЛЬНО

Инженерный стандарт (источники: UML state machine / Harel statecharts / GoF
State / Samek «Practical UML Statecharts» / практика Voice UI). Причина: в
2026-08-29 монолитный if/elif в plan_reply «дал трещину» — каждое новое
правило требовало ещё один флаг и ещё одну ветку. Перестройте на это:

1. **ОДНА таблица переходов на машину.** Всё управление — в declarative списке
   `(src, event, guard, action, dst)`. НЕТ разбросанных if/elif и ad-hoc
   флагов, которые живут в разных местах. Диспетчер = тонкий (классифицирует
   вход → событие → FSM.handle).
2. **Guard'ы — ЧИСТЫЕ предикаты** (только читают extended state, ничего не
   меняют). Если guard мутирует — порядок оценки становится ошибкой. Аction —
   единственное место, где пишут extended state.
3. **Run-to-completion (RTC):** один событие обрабатывается целиком, до конца,
   прежде чем следующее. Не пере-входи в машину из другого потока во время
   обработки (у неё нет внутреннего лока — это обязанность вызывающего).
4. **Необработанное событие = явное исключение → безопасный fallback.** Машина
   НИКОГДА не молчит на вход, который не понимает.
5. **«*»-источник выносит общий код** (опасность, done, repair) — иначе state
   explosion и повторение переходов в каждом состоянии.
6. **Entry/exit действия** гарантируют init/cleanup при входе/выходе из
   состояния — не дублируй их на каждом переходе.
7. **Extended state ≠ state variable:** счётчики (empty_turns), флаги
   подтверждений, позиция agenda живут на контексте (Agent), а НЕ плодят
   новые состояния. State = качественная фаза, extended = количественные
   переменные.
8. **Каждое новое правило = сперва регрессионный тест** (см.
   telephony/tests/test_dialogue_fixes_20260829.py + test_fsm.py), потом код.
   Машина не меняется без зелёного сьюта.

Реализовано: `telephony/core/fsm.py` (generic) + `DialogueFSM` в
`telephony/core/dialogue.py`. Новые правила диалога (прощание/отказ/anchor)
добавляются ОДНОЙ строкой в `_build_transitions()`.

## Ключевые решения (не переоткрывать)

- **Silero-VAD не потокобезопасен (2026-08-22):** TorchScript-модель хранит
  LSTM-state в себе; параллельный инференс из нескольких HTTP-потоков
  ломает state и валит процесс (`double free or corruption`). Весь инференс
  VAD сериализован RLock'ом в `vad_speech_seconds` ([tts_common.py](runtime/
  scripts/tts_common.py)). НЕ убирать лок ради «параллельности» — цена
  инференса ~10–50 мс, узким местом не является.

- LLM-интент ответа живёт в system-промпте (перенос в хвост ломает Qwen3:
  «ты» вместо «вы», выдумки — проверено, откатено).
- STT: int8 на ARM в 2 раза МЕДЛЕННЕЕ fp32; **tiny** точнее base на наших
  фразах; **3 потока/запрос** оптимальны (2.3 фразы/с на 10 ядер).
- **Шумовой гейт:** Silero VAD (torch.hub snakers4/silero-vad) — авторитет по
  длительности речи; < 0.15 с = нет речи (шум/ТВ не доходят до LLM). VAD
  недоступен → fail-open (не глухнем). ВАЖНО: hub возвращает (model, utils),
  get_speech_timestamps живёт в utils; torch импортировать в функции.
- **Кусочная запись от шума:** chunk 1 cap 4 с + chunks 2+ cap 2 с (макс 3);
  кусок, упёршийся в лимит, проверяется `/has_speech` — **хвост 1.2 с** +
  энергопорог (Silero VAD отличает голос в трубке от ТВ в комнате: дальний
  звук тише). Хвост без речи = конец хода. turn_stream принимает
  `"audio": [список кусков]` — склейка на сервере.
- **Гейт мусора по уверенности:** whisper-tiny на реальном телефоне даёт
  бессмыслицу («Сам оттвыж»), которую LLM эхом повторял. conf < 0.55 =
  пустой транскрипт («Повторите…»); чистая речь даёт 0.85+. Гейт в
  process_turn_stream (phone path).
- **Конверсационный repair:** «что ты сказала / повтори» → Вера повторяет
  свой предыдущий ответ (_last_reply), а не уходит в новую тему.
- **Темы вопросов Веры:** только самочувствие/забота (голова, давление,
  таблетки, сон, настроение, планы). ЗАПРЕЩЕНЫ: местоположение, адрес,
  личные данные. Симптом в реплике → обязательное уточнение про него
  («Как голова сейчас? Таблетка помогла?»).
- **Прощание с подтверждением:** короткое «до свидания» как ответ на вопрос
  о самочувствии → подтверждение («Вы сейчас прощаетесь?»), т.к. tiny путает
  «Да, всё хорошо» ↔ «До свидания!». Второй сигнал прощания завершает звонок.
- **Ведущее «нет» = отрицание:** «Нет, не сейчас хорошо» на контрольный
  вопрос — это ОТРИЦАНИЕ (жалоба относится к прошлому), а не подтверждение
  тревоги. Override в ОБОИХ complaint-блоках safety_engine (смежная фраза +
  окно ±3 токена). Реальный кейс: «Нет, не сейчас хорошо, а почему ты так
  подумал?» эскалировал в alert. После снятия тревоги — извинение и вопрос
  о самочувствии («Простите, я перестраховалась…»).
- **start_check_in() вызывается в new_call** — раньше не вызывался вовсе,
  машина проверки самочувствия не активировалась (companion по умолчанию).
- **Анти-повторы:** `_pick_not_repeated` на всех вопросных списках;
  предыдущий ответ показывается модели в интенте (не повторять вопрос);
  «РОВНО ОДИН вопросительный знак» в промпте.
- **Детектор выдумок:** `reply_looks_hallucinated` (оценки внешности/голоса)
  — сегмент заменяется скриптовым фолбэком ДО озвучки.
- LLM-интент ответа живёт в последнем сообщении ПОЛЬЗОВАТЕЛЯ (system —
  константа ради KV-кэша llama.cpp; интент в system ломал кэш каждый ход:
  +1–2 с). LLM keep-alive пинг каждые 45 с РЕАЛЬНЫМ системным промптом
  (пинг «ок» вымывал полезный кэш!) + `--mlock --no-mmap --cache-reuse 256`.
  Без этого первый ход после паузы 6–12 с.
- **Быстрый путь подтверждений:** короткие «да/хорошо/спасибо» отвечаются
  скриптовыми фразами БЕЗ LLM (0.6–0.75 с на ход вместо ~2.5 с).
- Детектор выдумок: `reply_looks_hallucinated` (оценки внешности/голоса)
  — сегмент заменяется скриптовым фолбэком ДО озвучки.
- STT: int8 на ARM в 2 раза МЕДЛЕННЕЕ fp32; **tiny** точнее base на наших
  фразах; **3 потока/запрос** оптимальны (2.3 фразы/с на 10 ядер).
- **Аудит-фиксы 2026-08-21 (№1–17):** SingleFlight-слот освобождается при
  обрыве клиента (иначе вечные 503), `notify_all()` в `_release`; миграции
  SQL+версия в ОДНОЙ транзакции; `incidents.maybe_open` идемпотентен по
  call_id (`get_incident_by_call`); `call.result` несёт `verdict`+
  `notes` (контракт консьюмера); fallback-аудио в orchestrator идёт через
  сегментный цикл (wire-кадры + seg-файл); `_help_pending` снимается только
  при обработке (не безусловно в `plan_reply`) — «да» на «Нужна помощь?»
  распознаётся; Lua: wall-time через счётчик waits (os.clock = CPU-время!),
  `safe_id()` санитизация call_id + кавычки в shell; tts_server: лок
  вокруг `_ensure_stt` (гонка двойной загрузки) и слот SingleFlight на
  `/transcribe`; multipart-парсер не режет тело `rstrip(b"\r\n--")`
  (портил WAV) + boundary с кавычками; HTTP: лимит тела 8 МБ
  (`_read_body`), HMAC-SHA256 `X-Moss-Signature` на `/webhook/provider`
  при заданном `MOSS_WEBHOOK_SECRET`; docker-compose порт tg на
  127.0.0.1; llm.py: partial-stream guard (нет локального фолбэка после
  начала выдачи — дубль текста) и `conn.close()` в finally (утечка при
  barge-in); s3_recordings: негативный кэш MinIO-падений
  `MOSS_S3_RETRY_SECONDS` (по умолчанию 60) под локом.
