# IMVERA: восстановление звука и выбор голоса

Дата: 6 сентября 2026. Проверенный коммит: `f71de9d8ba36609b116eb24dd63c7e88a94c05d7`, ветка `feature/voice-zoiper-m5`.

Этот пакет содержит воспроизводимые проверки трёх ошибок текущего кода и отдельный генератор кандидатов женского голоса для Apple Silicon. **Аудиофайлов в архиве нет: здесь нет Apple Silicon/MLX, поэтому генерация моделей не выполнялась.** Скрипт создаст настоящие синтетические WAV на Mac; готовые записи и студийное качество не заявляются.

## Что делать сейчас

1. Cursor исправляет ошибки из `AUDIT_f71de9d.md` и прогоняет `test_audio_delivery_regressions.py`. Основная задача — целиком слышимая фраза и правильно распознанный ответ в Zoiper.
2. После исправления аудиопотока запускается отдельная офлайн-процедура выбора голоса. Она не меняет работающий TTS worker или конфигурацию проекта.
3. Из 12 профилей / 24 кандидатов выбирается один референс, затем проверяется его повторное использование на новых фразах. Если качество и задержка подходят, Cursor подключает Base-модель с этим референсом к TTS worker.
4. Дообучение рассматривается только после сравнения с таким вариантом без обучения. Многоголосый набор нельзя напрямую смешивать в одноголосом обучающем скрипте Qwen.

## Создание кандидатов на Mac

Во время офлайн-генерации не проводить звонки; освободить память от ненужных модельных процессов. Не обновлять зависимости рабочего voice stack: использовать отдельное окружение.

Из распакованной папки:

```bash
python3 -m venv .venv-voicebench
.venv-voicebench/bin/python -m pip install -r requirements-voices.txt
.venv-voicebench/bin/python voice_workbench.py plan
.venv-voicebench/bin/python voice_workbench.py design --out candidates --limit 12 --takes 2
```

Первый запуск скачает реальный checkpoint VoiceDesign. Требуются доступ к GitHub/Hugging Face и свободные память и место. Веса VoiceDesign-8bit на странице модели занимают около 3,08 GB; это **не** оценка полного потребления RAM. Время генерации и пиковая память на вашем Mac не измерялись. Модели загружаются последовательно в разных запусках, а не вместе.

Результат: `candidates/listen.html`, 24 WAV при успешных генерациях, JSON для каждой записи и общий manifest. Откройте `listen.html` локально в браузере. Если часть генераций упала, скрипт вернёт ненулевой код и перечислит ошибки. Существующая папка не перезаписывается; для повторного запуска укажите новую.

Все кандидаты читают один и тот же текст. 12 описаний — это 12 целевых акустических профилей, а не гарантия 12 различимых или одинаково хороших голосов. Два дубля одного описания могут иметь разный тембр; выбранный WAV становится фиксированным референсом.

## Единый формат

- WAV, PCM signed 16-bit, mono, 24 000 Hz — исходная частота генерации этих моделей.
- Никакой телефонной компрессии или преобразования в 8 kHz в мастер-референсах.
- Контроль конечных чисел, моноформата, пустого/почти беззвучного выхода; ослабление громкости только при необходимости избежать клиппинга.
- Исходная частота проверяется; подмена частоты в заголовке и искусственное повышение частоты не выполняются.
- Метаданные: checkpoint и его фактический SHA, версии MLX, seed, текст задания, время генерации, длительность, peak/RMS, SHA256 WAV и происхождение `synthetic_voice_design`.
- `expected_text` — ожидаемый текст. Это не автоматически подтверждённая расшифровка.

Техническая валидность WAV не подтверждает дикцию, полную фразу, естественность или отсутствие акцента. Сначала прослушать, проверить текст и отбраковать неудачные дубли. Эти образцы не являются записями реальных дикторов.

## Один выбранный голос на новых фразах

Откройте JSON понравившегося дубля, например `candidates/v01_take01.json`. После прослушивания установите:

```json
"qa_status": "approved",
"verified_transcript": "Точные слова, которые действительно слышны в этом WAV."
```

Если есть проглоченные слова, артефакты или грубые ошибки произношения, выбрать другой дубль. Не объявлять ожидаемый текст расшифровкой автоматически.

Затем:

```bash
.venv-voicebench/bin/python voice_workbench.py clone --reference candidates/v01_take01.json --out chosen_voice_checks
```

Скрипт загрузит **Qwen3-TTS-12Hz-0.6B-Base-bf16** и создаст 10 новых реплик с одним и тем же референсом. Это кандидат для измерений, не установленный победитель по качеству или скорости. Для сравнения можно отдельным запуском передать другой проверенный Base checkpoint через `--model`.

Откройте `chosen_voice_checks/listen.html`. Проверьте стабильность тембра между фразами, русские вопросы, имена, числа, короткое «я подожду», исправления и завершение разговора. В manifest записана длительность генерации; `stream=False` выбран для оценки звучания, а не для оценки задержки первого чанка в звонке.

`evaluation_texts.json` — контрольные тексты для прослушивания, не разрешение произносить эти фразы в любом состоянии продукта. В рабочем диалоге содержание по-прежнему определяют Planner/State/Validator.

## Как подключить к продукту

Текущий worker использует `0.6B-CustomVoice` с `serena`. Эта модель выбирает встроенные голоса; текущий HTTP-контракт вообще не передаёт `ref_audio` / `ref_text`. Файла WAV рядом с моделью недостаточно.

Для выбранного референса Cursor должен добавить явный профиль `reference_clone`, загрузить соответствующую Base-модель и передавать ей проверенный `ref_audio` + `ref_text`. Разрешённый путь и хеш референса берутся из серверной конфигурации профиля. Голос для звонка фиксируется по `voice_profile_id` и версии. VoiceDesign используется офлайн для выбора; повторная генерация описания на каждом ходе не гарантирует постоянство голоса.

Перед заменой профиля измерить на этом Mac и на одинаковых русских текстах: время до первого PCM, время окончания синтеза, скорость генерации относительно длины аудио, потребление памяти, полноту речи и стабильность тембра. Проверить длительную фразу и перебивание в Zoiper после исправления транспортных ошибок.

## Почему не начинать с дообучения

VoiceDesign → фиксированный референс → Base cloning — документированный Qwen путь без реального диктора и без изменения весов. Он позволяет сначала услышать, подходит ли голос.

Официальный `finetuning/sft_12hz.py` на дату проверки описан как **single-speaker**. Для обучения одного голоса нужны согласованные примеры этого голоса и один устойчивый ref_audio. Смешивание 12 разных голосов как одного speaker создаёт противоречивую цель. Если позднее действительно нужен многоголосый обучаемый синтезатор, это отдельная задача с поддерживаемым multi-speaker trainer и явными speaker_id.

Синтетические данные сохраняют ошибки исходного генератора. Нужны отбор, точные тексты и отдельный контрольный набор; обучение не гарантирует улучшение естественности. Указанные checkpoints опубликованы под Apache-2.0. Не добавлять в корпус записи чужих дикторов или коммерческих TTS без проверки условий именно такого использования.

## Проверено в этом пакете

- API генератора сверены с исходным кодом MLX Audio; commit закреплён в `requirements-voices.txt`.
- Проверены Python syntax/lint, профильный JSON и запуск `plan`.
- На неподдерживаемой платформе генератор завершается с понятной ошибкой без подставного аудио.
- Сами нейросетевые WAV, естественность, стабильность тембра и скорость на Mac **не проверены и не заявлены**.
- Результаты проверки текущего проекта находятся в `AUDIT_f71de9d.md` и `verification_results.txt`.
